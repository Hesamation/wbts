THE TWO-MINUTE JUDGE GUIDE

Follow one deal.
Inspect what happened.

A data specialist should not deliver first and then hope the buyer pays. FactSettle holds the price on NEAR and checks each proof before allocating payment.

No wallet, sign-in or API key. These are recorded executions of the compiled contract in a local NEAR simulator, with constructed public data and distinct scripted signing accounts. Opening this demo sends no transactions.

1. See the complete payment

Open “Buyer won't approve” → The specialist earns 0.02 virtual NEAR for two valid fact openings, with no buyer approval transaction.

  1. Press Fund: the buyer's job price is locked.
  2. Press Accept: the named seller accepts the agreed dataset, keys and deadlines.
  3. Press Deliver: the contract has checked both openings and credited the seller's shares.
  4. Press Withdraw: the recorded transfers and callbacks have completed. The final wallet table separates payment, gas, retained storage and net wallet changes.

“Seller payment” is the job allocation, not profit. Retained storage is substantial for this illustrative small purchase.

2. Try the two failure cases

Seller invents a value → The altered opening is rejected. It earns no job payment; expiry credits the price back to the buyer, who withdraws it.

One fact never arrives → A delivered fact earns only its agreed share. An observer closes the expired remainder; the buyer receives that share back.

The other records cover proven absence, a seller that never accepts and buyer cancellation before acceptance.

3. Check the proof yourself

Return to the valid-delivery case and scroll to Change a value. Check again. The original value matches the root. Edit it, press Check proof, and see the mismatch.

Your browser independently hashes the opening through all 32 Merkle levels. This edits only the browser check. The recorded rejection case above is a separate contract execution.

A proof establishes consistency with the seller's committed dataset. The buyer must choose a dataset it trusts. It does not establish external truth, source authenticity, answer quality or fresh AI inference. Delivered entries and their proofs are public.

What NEAR does here

NEAR authenticates callers, holds the buyer-funded escrow, checks proofs and allocates credit atomically. Block deadlines allow unfinished work to be refunded. Transfers use private, nonce-checked callbacks so a failed transfer can restore credit.

No additional buyer approval is required after a valid delivery. Expiry still requires a caller; there is no background keeper. If the callback itself fails, a withdrawal can remain ambiguous and pending; there is no blind retry or administrative rescue promise.

This is a focused implementation of proof-verifying escrow for agent data jobs. The participants are scripted; the project does not claim live customers, a general agent marketplace or autonomous reasoning verification.

Inspect the execution records

The viewer checks each record's SHA-256 against the manifest before rendering. The manifest also identifies the executed WASM. These checks establish consistency with the bundled records, not independent chain inclusion or an audit.

Manifest and executed WASM digest ↗ Complete payment record ↓ Rejected answer record ↓ Partial delivery and refund ↓ Proven absence record ↓ Unaccepted offer record ↓ Cancellation record ↓ Upstream attribution and sample provenance ↗

Six executions contain 39 signed calls, six proof attempts and two expected rejections. Each record includes per-call receipts, job state, final accounting, wallet reconciliation and withdrawal outcomes.

Reproduce from source

Source repository (currently private) ↗ retains its historical WBTS URL. The README includes pinned toolchain instructions and the full test/export commands. The repository must be public before it can serve as a public hackathon submission.

From a repository checkout, the viewer needs only Python 3:

python3 -m http.server 8765 --bind 127.0.0.1 --directory demo

Open http://127.0.0.1:8765/. To independently check the committed records:

python3 scripts/check-data-demo.py
